# Official Runtime Lock

This directory is the reproducibility boundary for the official DeepSeek Harness
runtime embedded in Desktop release artifacts.

`package.json` intentionally contains exactly one runtime dependency:
`@deepseek-ai/dsh` at the repository's reviewed official pin.
`package-lock.json` is committed so Linux, Windows, and macOS release builds do
not independently re-resolve the 500+ package transitive tree.

`stage-official-runtime.mjs` copies this manifest and lock into an isolated
staging directory and runs `npm ci` **with lifecycle scripts enabled**. The
existing runtime checks then require the official CLI, transitive imports, the
platform node-pty binary, and the minimum runtime tar size before packaging.

## Current lock provenance

`evidence.json` records the GitHub Actions run, runner, Node/npm versions,
artifact ID, generated-lock SHA-256, and package count for the committed lock.
The upstream-contract suite recomputes the lock SHA-256 and checks it against
that evidence, in addition to the official pin and registry integrity fields.

The current lock was generated from the exact runtime-only manifest with:

```sh
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
```

It was **not** generated by a Desktop package install and does not contain
Community workspace packages.

## Pin bump procedure

When the official DSH pin changes:

1. update the repository's normal official-pin sources and this directory's
   `package.json` in the same change;
2. regenerate `package-lock.json` from a clean Node 22 environment;
3. review the lock diff, especially new registries, packages, lifecycle/native
   surfaces, and integrity changes;
4. update `evidence.json` from the generation run and exact lock SHA-256;
5. require normal CI, `runtime-lock-verify` on Linux/Windows/macOS,
   dependency audit, and the Windows protected-package smoke to pass.

Do not replace `npm ci` with `npm install` in release staging. A build that
needs a different dependency tree requires a reviewed lock update first.
