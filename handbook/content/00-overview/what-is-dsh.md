# dsh 是什么

## 一句话定义

DeepSeek Harness（命令通常写作 `dsh`）是一个用于运行 Agent 的开源 harness。它把模型请求、工具、工作区、会话、权限、审批和用户界面组装成一次可持续运行的任务，而不是只返回一段聊天文本。

官方项目把它描述为“一切皆插件”的系统，并由 Cordis 驱动。这句话很重要：Web UI、headless 运行器、模型适配器、工具注册表、会话存储、沙箱和审批策略都不是一个无法替换的单体内核，而是可以被组合和覆盖的能力。

## 它解决的不是“如何调用一次模型”

普通 API 调用通常是：

~~~text
输入消息 → HTTP 请求 → 文本回复
~~~

dsh 的典型任务更接近：

~~~text
用户目标
  → 选择模型和 Provider
  → 选择 profile 与组合
  → 打开 session
  → 读取 workspace 和上下文
  → 规划下一步
  → 请求模型
  → 调用工具
  → 接收工具结果
  → 继续轮次或停止
  → 保存事件、输出结果和退出原因
~~~

这使 dsh 能处理更长的工作，但也引入了更多需要人工管理的边界：

- 代理到底能访问哪个目录；
- 工具调用是否需要审批；
- Provider 会收到哪些输入；
- 一个 session 是否带着旧的 Shell 状态；
- 任务所谓的“完成”由什么外部结果证明；
- profile 升级后默认工具和权限是否改变。

## dsh、模型、Provider 和 Agent 的区别

| 对象 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 模型 | 生成下一步判断、文本和工具调用意图 | 不自动保证权限、事实正确或任务完成 |
| Provider | 把模型 ID、协议、端点和凭据接起来 | 不保证端点真的支持你声明的能力 |
| Agent | 在 session 中循环处理消息、工具和结果 | 不自动替你定义验收标准 |
| 工具 | 读取文件、搜索、执行命令、编辑或委派工作 | 不代表每次调用都安全或得到批准 |
| workspace | 提供任务的文件系统上下文 | 不等于完整的沙箱或数据边界 |
| session | 保存对话、事件和可恢复状态 | 不等于单纯的聊天记录 |
| profile | 决定运行时加载哪些组合 | 不等于任务文本或模型 |
| 组合包 | 向插件树增加能力和默认配置 | 不等于长期稳定的公开 API |

## 什么时候它有价值

dsh 适合需要“观察—行动—验证”闭环的工作，例如：

- 在一个仓库里定位测试失败并做小范围修复；
- 读取多个模块后生成有文件依据的架构说明；
- 在隔离工作区批量执行有明确验收器的维护任务；
- 让 Python 程序保留 session、事件和工作区状态；
- 通过插件组合改变工具、模型、权限或界面。

如果只是一次简单的问答，直接使用模型 API 或聊天页面通常更简单。Harness 的价值来自任务编排和边界控制，不来自把普通问答包上一层命令。

## Developer Preview 的现实含义

Developer Preview 不是“不能用”，而是不能把今天的配置当成永久接口。使用时要同时保存：

- dsh npm 包版本或源码 commit；
- Node/Python 版本；
- profile、组合和 patch；
- Provider ID、模型 ID 和协议；
- 任务模板和独立验收命令。

升级前先在临时 checkout 上复跑一条低风险任务，确认启动、凭据、模型、工具和退出码没有发生意外变化。
