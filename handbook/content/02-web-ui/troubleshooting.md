# Web UI 故障排查

## 页面打不开

按顺序检查：

~~~bash
node --version
npx @deepseek-ai/dsh web --help
curl -I http://127.0.0.1:3080
~~~

然后确认：

- dsh 进程是否仍在运行；
- 端口是否被其他程序占用；
- 浏览器访问的端口是否与终端打印的一致；
- WSL、容器或远程环境是否做了端口转发；
- 服务是否只绑定本机地址。

不要一开始就把服务绑定到 0.0.0.0。先用本机访问解决运行问题，再单独设计远程访问和认证。

## 页面能打开但不能输入

最常见原因是还没有选择 workspace。按 UI 提示添加项目目录并选中。然后确认：

- 选中的目录是预期项目；
- 目录权限允许 dsh 进程读取；
- 没有把文件路径写成另一运行时的格式；
- 当前 session 没有处在错误或只读状态。

## 配置模型后仍然失败

按错误分组：

- MISSING_CREDENTIAL：检查凭据引用、环境变量名和 DSH_HOME；
- UNKNOWN_MODEL：检查 Provider 是否保存、模型 ID 和模型选择器；
- 401/403：检查密钥、endpoint、组织权限和网络代理；
- 请求超时：检查端点连通性、模型负载和本地超时；
- 图片被拒绝：检查模型输入模态和当前 session 是否已记录旧图片。

不要反复点击发送来“碰运气”。每次重试前先确认错误发生在凭据、端点、模型、输入或工具层。

## 任务停在工具请求处

检查：

1. 是否有待处理审批；
2. 工具是否需要人类回答；
3. 当前权限是否拒绝；
4. 子进程是否仍在运行；
5. 会话是否被浏览器刷新或服务重启打断；
6. 工具结果是否返回但 UI 没有刷新。

先保存当前 session 和工作区状态，再尝试恢复或新建会话。

## 任务看似完成但没有改动

先看任务是否真的要求写入，再看：

- 当前权限是否为只读；
- Agent 是否只是提出了 patch 而没有执行；
- 文件是否在 workspace 外；
- 编辑工具是否因路径或内容匹配失败；
- 当前模型是否只返回计划；
- Web UI 是否显示了另一个 session。

检查工具事件和实际 diff，不要以最终回答判断。

## 任务改动了不该改的文件

立即暂停：

~~~bash
git status --short
git diff --stat
git diff --name-only
~~~

不要先运行格式化或自动修复，否则会扩大现场。记录 session、时间、最后一条工具请求和当前权限，然后回滚或从干净副本重做。
