# 目录 Provider

## 目录的意义

已安装目录 Provider 的价值是把常见端点、协议、认证方式和模型能力整理成可选择项。它并不消除认证或网络问题，也不保证每个模型在所有账号和区域可用。

## 原生认证不是 API key 表单

官方指南特别提醒，某些 Provider 使用原生认证：

| Provider 类型 | 可能需要的材料 |
| --- | --- |
| AWS Bedrock | AWS 凭据和区域 |
| Vertex | ADC 项目或区域配置 |
| Azure | endpoint、api-version 和凭据 |
| Codex/OAuth 类 | OAuth 登录或刷新状态 |
| 普通兼容端点 | API key、Base URL、协议和模型 |

表格只是理解认证形态的分类，不是替代当前 Provider 文档的固定字段表。

## 配置步骤

1. 从 Add Provider 进入目录；
2. 选择已安装的 Provider；
3. 按该 Provider 的字段完成认证；
4. 保存；
5. 选择模型；
6. 新建 session 做最小请求。

不要把“卡片显示出来”当成认证完成。认证完成要看保存结果和实际请求。

## 目录与网络

官方资料区分两类行为：

- 已安装目录本身提供的端点、协议和模型列表不一定需要网络查询；
- 自定义 Provider 的获取可用模型会请求当前表单的 endpoint。

运行模型目录查询前确认网络边界和凭据作用范围。若公司网关没有 GET /models，手动添加模型 ID，避免为了目录接口修改网关。

## 切换 Provider 的方法

要比较不同 Provider：

- 使用两个新 session；
- 任务文本保持一致；
- workspace 使用同一份只读副本；
- 记录模型、协议和端点的脱敏标识；
- 比较工具调用、错误和外部验收，不只比较最终文字。

如果要把旧 session 切到新 Provider，先确认历史日志和当前任务是否允许切换；最稳妥的做法通常是新建 session 并复制已确认背景。
