# Provider 基础概念

## Provider 不是模型别名

一次模型请求至少要回答：

1. 发送到哪个 URL；
2. 按哪种 API 协议编码；
3. 用哪个凭据；
4. 使用哪个模型 ID；
5. 输入中是否含图片等模态；
6. 请求属于哪个 session。

Provider 把前五项组合起来，session 再记录本次任务使用的模型和事件。

## ID 与显示名称

Provider ID 是持久标识，可能被以下对象引用：

- 已保存 session；
- 默认模型；
- 凭据引用；
- 请求和配置 patch；
- 脚本或团队文档。

显示名称面向人，可以调整；Provider ID 应稳定。需要改名时，新建 Provider、迁移引用，再删除旧 Provider。不要直接在配置文件中把旧字符串批量替换，然后期待历史 session 自动迁移。

## 目录 Provider 和自定义 Provider

目录 Provider 由已安装的 Provider 目录提供端点、协议和模型列表。它适合常见服务和原生认证。

自定义 Provider 适合公司网关、自建服务或目录中不存在的端点。它要求你自己确认协议和模型能力，dsh 不会因为你填写了字段就自动证明端点正确。

## 模型目录查询

OpenAI 兼容的模型目录通常通过 GET /models 查询。目录查询有两个边界：

- 查询发生在当前表单显示的 endpoint 和凭据下；
- 查询到的候选项可能只更新草稿，保存 Provider 是另一个动作。

如果端点不提供模型目录，不要把 401 或 404 解释成“没有模型”。改为手动填写准确的模型 ID，并用一个低风险请求验证。

## 模型选择与 session

新建 session 会使用当前默认模型。已经发送过请求的 session 通常保留自己的模型记录。因此修改默认模型后：

- 新 session 使用新模型；
- 旧 session 可能继续显示旧模型；
- 要比较两个模型，使用相同任务文本和两个新 session；
- 不要在比较过程中混用旧上下文。

## 端点与数据流

Base URL 不只是网络地址，它决定代码和工具结果可能送往哪里。配置公司网关时确认：

- TLS 和证书；
- 代理和 DNS；
- 请求保留和审计策略；
- 是否把工具结果转发到第三方；
- 错误日志是否包含 prompt 或响应；
- 图片是否被保存或缓存。
