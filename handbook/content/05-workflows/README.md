# 任务工作流

Agent 不是“把一句话变成长答案”的工具，而是会观察、调用工具、改变状态并继续判断的运行时。工作流的核心是把目标变成可执行范围，再把结果交给外部验收。

## 本章主线

先走[从空白 workspace 到可验收交付](from-blank-to-delivery.md)。它把本章的原则串成一次完整任务：建立基线、只读理解、收敛计划、最小修改、独立验证、交付或恢复。走完主线后，再按下面的专题处理具体任务。

## 所有任务都要有的六项

~~~text
目标：最终要交付什么
范围：允许观察和修改哪些位置
不变量：哪些东西不能改变
权限：允许读、写、执行、联网到什么程度
验收：哪些外部检查通过才算完成
停止：什么情况下必须暂停并询问
~~~

恢复信息可以作为第七项加入：最后一个已确认步骤、当前 diff、session、测试结果和回滚方式。

## 观察、行动、验证

~~~text
观察：读取文件、状态、配置、错误
行动：编辑、运行命令、安装、联网、委派
验证：测试、构建、diff、人工检查、结果比对
~~~

这三个阶段可以交错，但不能把行动写成观察，也不能把模型的自我描述写成验证。

## 任务大小

如果一个任务同时包含多个目标，先拆成阶段：

- 阶段一：只读理解；
- 阶段二：提出修改方案；
- 阶段三：实施最小改动；
- 阶段四：运行验证；
- 阶段五：整理交付。

每阶段都有停止条件。拆分不是为了增加文档，而是为了让错误不会一路扩散。
