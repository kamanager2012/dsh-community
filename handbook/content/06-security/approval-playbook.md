# 审批操作手册

## 低风险动作

通常可以在明确只读范围内批准：

- 列目录；
- 读取指定文本；
- 搜索指定目录；
- 查看 Git 状态；
- 运行不会写入的测试或类型检查。

仍要检查测试工具是否会生成缓存、覆盖快照或写入临时文件。

## 中风险动作

需要看清范围和回滚：

- 修改指定源码；
- 运行项目测试；
- 生成文档或构建产物；
- 修改配置；
- 创建临时分支；
- 启动本地开发服务。

批准前确认输出目录、端口、生成物和依赖变化。

## 高风险动作

默认暂停并转人工：

- 读取凭据、生产数据或客户文件；
- 修改 workspace 外路径；
- 安装并执行未知依赖；
- 上传文件或向新 endpoint 发请求；
- 删除、迁移、覆盖数据；
- 修改权限或沙箱；
- 使用 danger-full-access；
- 提交、推送或发布外部变更。

即使业务允许，也要写出理由、范围、时间、审批人和回滚。

## 审批卡片

每个高影响批准应能回答：

~~~text
动作：
目标：
路径/命令：
输入来源：
网络：
权限：
预期副作用：
验证：
回滚：
批准人：
~~~

如果 UI 没有显示足够上下文，先让 Agent 输出计划或人工补充上下文，不要盲批。

## 拒绝后的处理

拒绝后要求 Agent：

- 解释为什么需要该动作；
- 给出不需要该权限的替代方案；
- 更新任务范围；
- 记录被拒绝的动作；
- 停在当前检查点。

不要让模型反复改写同一句请求直到有人误点批准。
