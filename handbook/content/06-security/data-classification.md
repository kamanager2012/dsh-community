# 数据分类与任务分级

## 任务分级

### L0：公共、只读

公共代码、公开文档、只读分析。允许较宽的模型访问，但仍要检查网络和第三方插件。

### L1：内部、可恢复

内部代码或配置的临时副本。需要批准 Provider、日志和保存位置，默认不允许向无关服务发送。

### L2：敏感、有限写入

含个人信息、内部凭据引用或重要业务逻辑。使用隔离环境、最小工具、人工审批和短日志保留。

### L3：生产或受监管

生产数据、密钥、客户记录、金融/医疗/法律材料。默认不直接交给通用 Agent；需要组织级安全审查和专门执行路径。

## 数据处理表

| 数据 | 是否可进入任务 | 需要的控制 |
| --- | --- | --- |
| 公共 README | 通常可以 | 许可、网络和工具边界 |
| 私有源码 | 需确认 | Provider、保留、日志和访问 |
| .env/密钥 | 不应进入 | 排除路径、凭据管理 |
| 客户数据 | 默认不进入 | 脱敏、审批、区域和保留 |
| 构建日志 | 需扫描 | token、路径、参数脱敏 |
| 图片/截图 | 需检查 | 个人信息、密钥、端点能力 |
| session JSONL | 受控保存 | 权限、保留、加密和删除 |

## 从 L0 升级到 L1/L2

升级前需要回答：

- 任务为什么必须读取更多数据；
- 需要哪个 Provider；
- 是否可用脱敏副本；
- 谁批准；
- 结果保存在哪里；
- 如何清理；
- 失败如何回滚。

如果回答不完整，停在较低级别，不要由 Agent 自己判断可以升级。

## 组织策略

团队可以在 profile 和 CI 外层定义数据分级门禁，但不要把一个 prompt 当成唯一控制。控制应同时存在于 workspace、进程、Provider、日志、网络和审批层。
