# 数据流与隐私

## 先画出数据流

~~~text
用户输入
  → dsh 任务文本
  → system prompt / session history
  → Provider endpoint
  → 模型请求
  → 工具调用
  → workspace 文件或外部服务
  → tool result / session log
  → Web UI、CLI stdout 或 SDK 结果
~~~

每个箭头都可能改变数据的范围。不要因为 dsh 在本机启动，就说“数据没有离开本机”。

## 开启网络前回答六个问题

1. 哪些输入会发送到哪个 Provider；
2. 是否包含私有代码、客户数据、路径、凭据或内部提示；
3. Provider、网关、MCP 和插件会不会保存；
4. 工具结果和 session 日志保存在哪里；
5. 是否有遥测、代理或第三方 API；
6. 任务结束后怎样清理。

官方隐私和数据处理说明是起点，但具体 Provider、公司网关和插件可能有独立政策。正式使用前由数据所有者或安全负责人确认。

## 输入分类

| 类别 | 示例 | 默认处理 |
| --- | --- | --- |
| 公共代码 | 开源仓库 | 仍检查许可证和网络 |
| 内部代码 | 未公开仓库 | 先确认 Provider 允许 |
| 个人信息 | 联系方式、账户信息 | 脱敏或禁止发送 |
| 凭据 | key、token、cookie | 禁止进入任务和日志 |
| 生产数据 | 用户记录、订单、数据库 | 使用隔离副本和组织审批 |
| 生成结果 | patch、报告、日志 | 脱敏后再共享 |

## 工具结果的二次泄露

即使任务文本没有秘密，Agent 运行命令也可能把秘密带进：

- stdout/stderr；
- grep 或搜索结果；
- 环境诊断；
- Git diff；
- session JSONL；
- Web UI；
- Provider 请求；
- CI 构建产物。

对包含秘密风险的目录设置明确排除项，不让模型“自己决定哪些不该看”。

## Provider 政策与组织政策

组织使用时要记录：

~~~text
Provider：
Base URL：
数据区域：
传输加密：
保留时间：
训练/评估用途：
管理员可见范围：
删除流程：
~~~

缺少这些信息时，不能把任务标为适合处理内部或受监管数据。
