# 越界与事故处置

## 发现异常后的第一分钟

1. 暂停 Agent 或拒绝当前审批；
2. 停止后台命令和可能的子进程；
3. 不要继续让模型“清理现场”；
4. 保存脱敏时间线；
5. 检查工作区 diff、凭据和外部请求；
6. 通知负责人员。

## 现场记录

~~~text
发生时间：
运行版本：
profile：
workspace：
session：
Provider：
权限：
触发动作：
已读取：
已写入：
已联网：
凭据是否可能暴露：
当前进程：
当前 diff：
~~~

只保存必要信息。日志中发现 token 时，先按泄露处理，再决定如何共享报告。

## 回滚和重建

不要在同一污染 session 中继续修复。优先：

~~~text
保留现场
  → 撤销/轮换凭据
  → 从干净 checkout 重新建立
  → 用新 session 重述任务
  → 降低权限并重新验证
~~~

工作区回滚前确认哪些改动原本属于用户。不要用破坏性 Git 命令覆盖未审查的用户改动。

## 事故后的改进

复盘要回答：

- 哪个边界没有写清；
- 哪个权限让动作成为可能；
- 哪个审批上下文缺失；
- 哪些日志不够；
- 哪个 Provider 或插件扩大了数据流；
- 如何让同类任务在下一次更早停止。

不要把事故归结为“模型偶尔犯错”就结束。需要改任务模板、profile、沙箱、审批、日志或团队流程。
