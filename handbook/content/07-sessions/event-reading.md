# 读取 Session 事件

## 为什么需要事件视角

最终回答只覆盖交付文本。事件视角能回答：

- 输入何时进入；
- 模型请求是否发出；
- 工具调用是否实际执行；
- 是否有多个 step；
- 子 Agent 是否产生后代；
- session 在哪里停止；
- 是否追加了新事件；
- 错误发生在模型、工具还是运行时。

## 事件范围

不同入口对 events、notifications、history 和持久化的范围可能不同。比较结果时先写清：

~~~text
读取的 session：
根/子 session：
事件范围：
通知范围：
序列范围：
时间窗口：
是否包含后台任务：
~~~

不要把通知数量当成工具调用数量，也不要把根 session 没有事件当成整个运行没有动作。

## 结束原因

每个 turn/step 都应有结束语义。报告中区分：

- 正常完成；
- 用户停止；
- 权限拒绝；
- 工具错误；
- 模型错误；
- 超时；
- 协议错误；
- 进程崩溃。

没有明确结束原因时，把状态写成未确认，不要猜。

## 事件与工作区对照

事件能说明 Agent 试图做什么，workspace 和进程状态说明外部发生什么。复核表：

| 事件信息 | 外部对应 |
| --- | --- |
| tool/call | 实际进程/文件/请求 |
| tool/result | 退出码和输出 |
| turn/end | 任务进程和验收 |
| session event | JSONL 和可重放状态 |
| notification | 子 Agent 或 UI 状态 |

事件与外部状态冲突时，以可复查的外部状态为准，并记录冲突。

## 脱敏读取

读取 session 日志前设置只读副本或脱敏管道。不要让排错 Agent 读取整个日志目录；先按 session ID 和时间范围筛选，排除凭据、图片和无关任务。
