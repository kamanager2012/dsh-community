# 会话持久化与日志

## 为什么要保留事件

事件日志可以支持：

- 任务重放和历史展示；
- 结果和工具动作的关联；
- resume/fork；
- 事故调查；
- 外部验收；
- 从一段长任务中提取阶段检查点。

但日志也是数据副本。它可能包含模型请求、工具参数、文件路径、命令输出、图片和错误信息。

## 日志的边界

按使用的 profile 和组合，日志可能保存在 DSH_HOME 或 SDK 传入的 session_root。不要猜路径。启动前查看当前版本文档、配置导出和实际目录。

日志目录要：

- 不提交 Git；
- 权限只给需要的人；
- 与生产秘密分开；
- 设置保留和清理策略；
- 上传前脱敏；
- 记录版本和 schema 变化。

## 事件与最终回答

最终回答是派生交付文本，不是完整轨迹。完整验收要同时考虑：

~~~text
assistant 文本
+ turn/step 结束原因
+ 工具调用和结果
+ 异常/进程状态
+ workspace diff
+ 外部测试
~~~

事件数量也不等于任务成功。子 Agent、后台任务和通知可能有不同范围。

## JSONL 日志处理

如果 SDK 或示例产生 JSONL：

1. 按行读取，不假设整文件是一个 JSON 对象；
2. 校验事件类型和 session ID；
3. 对字符串字段做 token、Cookie、路径和个人信息脱敏；
4. 保留时间顺序和结束原因；
5. 将摘要与原始日志分开保存；
6. 日志不可解析时标记为协议或环境失败，不要猜结果。

## 清理

清理前确认任务已经完成、事故现场不再需要、用户改动已交付。凭据、session、临时 workspace 和构建产物分别清理，不要一条递归删除命令扫掉整个 DSH_HOME。
