# Session 恢复与清理

## 恢复前的检查点

~~~text
session ID：
parent ID：
workspace：
cwd：
Provider/模型：
profile：
权限：
最后完整 turn：
当前 diff：
最后通过的测试：
未完成工具：
日志位置：
~~~

缺少 workspace、权限或最后完成边界时，不要直接点击继续。

## 按故障类型处理

### 浏览器关闭

重新打开页面，确认 session、workspace 和运行状态。若只剩历史文本，按“历史可读、运行时未确认”处理。

### dsh 进程退出

先检查进程退出原因和 workspace，再决定重启服务、恢复 session 还是新建 session。不要让重启后的默认 workspace 替代原 workspace。

### 模型请求失败

保存错误和当前 session。凭据或端点修复后，是否重试由任务影响决定；已包含图片或外部输入的 session 可能更适合新建。

### 工具或后台任务挂起

查询工具和进程状态。确认没有后台进程继续写入，再重启或清理。不要把“页面没有动”当作进程已经停止。

### 工作区出现异常 diff

暂停、保存 diff、找出首个写入动作。不要让 Agent 再运行格式化或清理命令掩盖现场。

## 什么时候 fork

Fork 适合保留已完成的父任务，同时尝试另一种实现或分析路线。它不适合：

- 修复一个已经污染的上下文；
- 隐藏失败；
- 代替备份；
- 把不同项目合并到一个 session。

污染 session 应新建，并明确复制哪些已确认事实。

## 清理顺序

~~~text
停止任务和后台进程
  → 保存必要的交付与脱敏日志
  → 检查 workspace diff
  → 交付或回滚
  → 删除临时 workspace
  → 清理 session 和凭据引用
  → 检查没有遗留进程与端口
~~~
