# 批处理与隔离

## 单任务先于并发

在并发前先证明单任务能够：

- 创建隔离 workspace；
- 使用固定 Provider 和模型；
- 按退出码结束；
- 运行独立验收；
- 清理 session、进程和临时目录。

并发只放大现有问题，不会自动提升可靠性。

## 每个任务独立的东西

~~~text
任务 ID
workspace
session ID
session_root
日志文件
临时端口（如需要）
预算/超时
清理责任
~~~

共享只读的代码基线可以接受，共享可写 workspace、session root 或凭据目录通常不行。

## 重试隔离

重试时决定是：

- 重用同一 session：保留上下文，但也保留错误和输入；
- 新建 session：清除上下文污染，但要重新说明背景；
- fork：保留父任务并尝试另一条路线。

不要把每次失败都自动 fork，否则会产生大量无法解释的结果分支。

## 成本和预算

为批处理设置：

- 最大任务数；
- 最大并发；
- 单任务时间；
- 单任务模型预算；
- 重试次数；
- 总预算；
- 人工暂停条件。

预算超出时停止并报告，不自动换更高成本模型或权限。

## 清理验收

批处理结束后检查：

~~~text
没有遗留 dsh 进程
没有遗留子进程
没有异常端口
没有未清理临时 workspace
没有含秘密的公共日志
每个任务都有状态和失败原因
~~~

## 适合批处理的任务

适合的是输入和验收相对固定的任务，例如每个包运行同一套只读检查或生成同一格式报告。需要大量人工判断、跨项目共享上下文或不可逆写入的任务，不要直接批量化。
