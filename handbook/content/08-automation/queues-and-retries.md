# 任务队列、重试与人工介入

## 队列状态机

外层系统可以用以下状态：

~~~text
queued
  → prepared
  → running
  → validating
  → completed
             ↘ needs-review
  ↘ blocked / failed
~~~

dsh 退出码只是其中一个输入。队列还要看 workspace、验收、清理和人工状态。

## 重试矩阵

| 错误 | 是否自动重试 | 处理 |
| --- | --- | --- |
| 参数错误 | 否 | 修复任务或配置 |
| 缺凭据 | 否 | 人工配置 |
| 短暂网络 | 有界 | 退避、计数、同一输入 |
| 401/403 | 否 | 检查账号/策略 |
| 429 | 有界 | 预算和限流 |
| 工具写入后失败 | 默认否 | 保留现场，人工判断 |
| 测试失败 | 默认否 | 分析 diff 和失败 |
| 进程崩溃 | 有界 | 检查子进程和 session |
| 模型输出不确定 | 否 | 改任务或转人工 |

## 重试前必须保存

~~~text
原任务：
版本/profile：
workspace 基线：
session：
已产生 diff：
已发送数据：
失败原因：
重试是否新 session：
~~~

不保存这些就重试，可能把失败上下文和工作区污染叠加。

## 队列的人工门

以下条件让任务进入 needs-review：

- 输出和测试冲突；
- diff 超出允许范围；
- 需要新增 Provider 或权限；
- 产生图片或敏感数据；
- 子 Agent 结果互相矛盾；
- session 无法恢复；
- 自动清理失败。

## 并发控制

并发不仅是进程数，还包括：

- Provider 限流；
- CPU、内存和磁盘；
- workspace 数量；
- session 日志写入；
- 后台端口；
- 人工审批能力。

先限制并发，再优化吞吐。
