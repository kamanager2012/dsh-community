# 工具类别与常见名称

官方工具目录会随发行版和组合生成，名称、参数和是否加载都可能变化。下面是理解工具边界的分类，不替代当前版本的 schema。

## 文件工具

常见能力包括：

| 能力 | 常见名称 | 作用 |
| --- | --- | --- |
| 读取 | read | 读取文本文件 |
| 写入 | write | 创建或覆盖文件 |
| 编辑 | edit、str_replace_editor | 按编辑操作修改文件 |
| 图片读取 | read_image | 读取图片并交给支持图像输入的模型 |
| 搜索文件 | glob | 按路径模式列出文件 |
| 搜索内容 | grep | 在文件中查找文本 |

文件工具通常受 ctx.fs、workspace、权限和观察策略影响。名称可变，不要在脚本中只靠显示名称判断权限。

## Shell 与进程

常见能力包括：

| 能力 | 常见名称 | 风险 |
| --- | --- | --- |
| 一次命令 | bash、pwsh | 读写、网络、安装、删除 |
| 持久终端 | persistent bash | 保留 cwd、环境、Shell 状态 |
| 后台任务 | run_in_background、job_* | 进程继续运行和写入 |
| 代码运行 | run_code | 组合语言运行时的额外能力 |

Shell 能看到的环境可能比 workspace 大。命令参数要按 shell 解释规则检查。

## 计划与协作

常见能力包括：

- exit_plan_mode：结束或提交计划审查；
- ask_user_question：向用户请求缺失决策；
- subagent 工具：委派子任务；
- agent 等待、结果和取消工具；
- 动态插件工具：按 profile 显式启用时才出现。

这些工具改变的是协调方式，不自动提升事实正确性。子 Agent 的结果也需要外部验收。

## 如何确认当前工具

先查看当前版本配置和帮助，再观察系统提示词或 UI 显示的工具目录。不要把一份官方工具目录复制成“所有部署都一定拥有的工具”。

## 工具与输入模态

read_image 需要图像能力的模型路由。模型声明 input 不是端点能力探测；如果端点实际不支持图片，Provider 仍可能拒绝请求。
