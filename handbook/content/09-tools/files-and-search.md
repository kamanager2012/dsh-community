# 文件与搜索工具

## 先发现再读取

文件任务建议按以下顺序：

1. 查看目录和版本控制状态；
2. 用 glob 缩小候选；
3. 用 grep 查找符号或配置；
4. 读取少量相关文件；
5. 确认路径后再编辑。

不要一开始把整个仓库所有文件都读入上下文。大仓库要排除构建产物、依赖目录、缓存、秘密和二进制。

## 读取

读取前确认：

- 文件路径属于任务范围；
- 文件不是凭据、客户数据或不可公开日志；
- 文件大小可接受；
- 需要完整内容还是片段；
- 结果是否会被发送给 Provider。

读取一个文件不代表允许读取它引用的所有文件。任务范围仍然有效。

## 编辑

编辑前：

- 先读取当前内容；
- 确认唯一匹配和上下文；
- 设定允许写入目录；
- 说明是否允许创建新文件；
- 做小步修改并运行相关检查。

编辑后：

~~~bash
git diff --name-only
git diff --check
~~~

如果编辑失败，不要盲目重复相同替换。检查文件已被其他动作修改、换行格式或匹配内容。

## 搜索结果上限

glob、grep 等工具可能对结果数量、大小和路径进行限制。结果被截断时，不能把“没有显示”当成“没有匹配”。缩小目录和模式，再分批搜索。

## 生成物和符号链接

确认工具如何处理：

- 符号链接；
- 忽略文件；
- 生成目录；
- 隐藏文件；
- 编码和换行；
- 超大文件；
- 二进制。

安全任务中对符号链接要格外小心：路径看起来在 workspace 内，实际目标可能在外部。
