# 计划、用户询问与子 Agent

## 计划工具

计划适合把长任务拆成可交付阶段。计划不是权限，也不是验收结果。批准计划后，Agent 仍需在每个高影响动作前遵守权限和任务范围。

计划应包含：

~~~text
阶段：
目标：
输入：
允许动作：
交付：
验收：
停止条件：
~~~

## ask_user_question

用户询问工具适合缺少业务决策时暂停，例如：

- 两个 API 兼容方案选哪个；
- 是否允许新增依赖；
- 是否可修改配置；
- 失败后继续还是交付部分结果。

不要让模型用默认猜测替代必须由用户决定的选择。

## 子 Agent

子 Agent 适合并行只读分析、独立测试或把一个大目标拆成互相隔离的子任务。委派前写清：

- 子任务目标和范围；
- 是否只读；
- workspace 和 session；
- 输出格式；
- 不能执行的动作；
- 谁负责最终验收。

子 Agent 的结果不能直接当作主任务事实。重复结论要回到文件、命令和工具结果。

## 动态工具或插件

动态 Cordis 工具能改变运行时工具集合，风险高于普通只读工具。只在明确 profile 和隔离环境中启用，并审查它能访问的 context、代码和进程。

## 协作结果

主 Agent 收集子任务时，保留：

~~~text
子任务 ID：
输入范围：
实际工具：
结果摘要：
失败：
未确认：
主任务如何验证：
~~~

不要只把多个 Agent 的最终文本拼起来当成报告。
