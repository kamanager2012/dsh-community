# 如何读工具 Schema

## Schema 告诉你的信息

每个工具 schema 至少包括：

- name；
- description；
- parameters；
- 必填字段；
- 枚举和默认值；
- 结果或错误形式。

它不一定告诉你完整的文件、网络、进程和权限边界。还要看工具依赖的 service、profile 和沙箱。

## 从 schema 反推风险

| 参数 | 可能的风险 |
| --- | --- |
| path | 路径越界、符号链接、敏感文件 |
| command | shell 注入、删除、安装、联网 |
| cwd | 任务边界改变 |
| run_in_background | 进程遗留和异步写入 |
| model/provider | 数据流和成本变化 |
| input/image | 私有内容和端点能力 |
| session_id | 上下文污染 |
| maxParallel | 资源和限流 |
| patch/package | 动态改变运行时 |

参数描述中若没有写清边界，不能默认安全。

## schema 不是权限

工具可能在 schema 中可见，但调用时被审批、沙箱、Provider 或用户拒绝。也可能 schema 不可见，因为当前 profile 没有加载工具。

报告工具问题时同时写：

~~~text
schema 可见：
调用被提出：
调用被批准：
调用执行：
外部结果：
~~~

## 工具目录的版本问题

官方工具目录是生成或维护的参考，可能按默认配置描述。自定义 profile、MCP 和动态插件会改变实际工具集合。升级后比较工具名称、参数和提示词描述，尤其是高风险工具。

## 设计自己的工具

自己的工具应默认：

- 参数尽量窄；
- 路径使用允许列表；
- 网络域名固定；
- 输出脱敏；
- 失败可重试或可停止；
- 有明确取消和清理；
- 不隐式提高权限。
