# Shell、后台任务与终端

## 一次性 Shell

一次性命令适合短、可观察、可重复的检查。任务中写明：

- 工作目录；
- 允许命令；
- 超时时间；
- 输出限制；
- 退出码如何处理；
- 是否允许网络和写入。

不要把复杂 shell 逻辑交给模型后再凭最终文本猜它运行了什么。保留实际命令和结果。

## 持久 Shell

持久 bash 可能保留：

- 当前工作目录；
- 导出的环境变量；
- shell 函数；
- 后台作业；
- 临时文件；
- 上一任务留下的状态。

因此同一个 session 复用持久 Shell 可能让新任务继承旧上下文。独立任务使用新 session 或显式清理。

## 后台任务

后台任务适合长时间构建、测试或服务器，但风险是 Agent 可能先结束而进程继续运行。

启动后记录：

~~~text
job ID：
进程：
工作目录：
日志：
端口：
预计结束条件：
停止命令：
~~~

任务交付前确认 job 已完成或已停止。不要只看 Agent 最终回答。

## PowerShell 与 Bash

bash 和 pwsh 的变量、路径、引号、管道和命令名称不同。不要把一套命令跨平台直接复制。任务模板写明当前 shell 和操作系统。

## 网络命令

curl、npm、git fetch、包管理器和下载工具都可能将数据发送到外部。网络允许不等于所有 endpoint 都允许。写出域名、用途、是否上传 workspace 内容和凭据范围。
