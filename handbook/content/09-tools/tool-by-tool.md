# 常见工具逐项说明

## read / write / edit

read 用于观察，write 和 edit 会改变 workspace。编辑前应先读取；编辑后要用 diff 检查。write 可能创建覆盖文件，edit 可能依赖唯一匹配和当前内容。

批准编辑时看：

- 路径；
- 修改类型；
- 是否在允许目录；
- 是否覆盖用户改动；
- 是否产生生成物；
- 验收和回滚。

## glob / grep

glob 查路径，grep 查内容。它们适合缩小范围，但结果可能受忽略规则、上限、二进制和符号链接影响。

搜索任务要写：

~~~text
搜索根目录：
包含模式：
排除目录：
是否读二进制：
结果上限：
输出用途：
~~~

## bash / pwsh

Shell 可以把 Agent 从文本生成变成真实系统操作。命令审查要看完整 argv、cwd、环境、管道、重定向、命令替换和退出码。

不要仅因为命令是 npm test 就认定无写入；测试可能生成缓存、覆盖快照或访问网络。

## persistent bash

持久 bash 适合需要连续上下文的任务，但会保留状态。独立任务不要复用。结束前清理函数、变量、后台任务和临时目录，或直接使用新 session。

## job_* 与后台执行

后台任务必须有查询、等待和停止路径。交付前不能有未解释的 job。服务器、watcher 和测试进程尤其容易遗留。

## ask_user_question

它把缺失的业务选择交回人。好的问题包含选项、影响和默认建议；不应把复杂的安全决定压缩成“继续吗”。

## exit_plan_mode

它表示计划阶段结束或等待审查。计划通过不是工具权限通过；实际编辑和执行仍按审批策略处理。

## subagent

子 Agent 可以分工，但要隔离输入、workspace 和结果。主 Agent 负责合并和最终验收。
