# Cordis 入门

## 五个核心概念

1. 插件是实现 Service 的对象；
2. Context 是服务容器；
3. inject 声明插件依赖；
4. 类型化事件负责通信；
5. 注册是可逆副作用。

插件应等待依赖服务就绪，而不是假设某个文件已经按顺序加载。事件应使用公开的分发模式，不能随意把观察事件当成可修改的 waterfall。

## 四种事件分发

| 模式 | 特征 | 适用 |
| --- | --- | --- |
| emit | 不等待、按顺序观察 | 广播事实 |
| waterfall | 环绕中间件，可通过 next 传递结果 | 修改或拦截决策 |
| parallel | 等待并行监听器 | 独立观察 |
| serial | 按顺序等待并返回结果 | 有序决策 |

Waterfall 监听器不调用 next 会短路下游。这是设计能力，不是偶然副作用；使用前要确认你是否真的拥有决策权。

## 配置加载

组合配置可以通过 bundle、profile patch、home patch 和 overlay 层叠。环境选择应优先使用明确的 overlay，避免把机器特定判断写进通用 bundle。

配置字段的最终含义以当前生成的配置目录和源码为准。插件文档中要写清：

- 提供了哪些服务；
- 依赖哪些服务；
- 注册哪些事件；
- 增加哪些工具；
- 默认权限和网络；
- 如何卸载和清理。

## 插件实践规则

- 工具流水线策略监听 ctx.tools 事件；
- 模型流处理使用 ctx.llm seam；
- Agent 协调使用 ctx.agents；
- 直接能力调用优先使用服务方法；
- 行为拦截优先使用事件；
- 每个资源注册都要有 disposer；
- 不把内部 context 键当成普通用户 API。
