# CI 与流水线

## 适合接入 CI 的任务

适合的任务具备：

- 固定输入格式；
- 隔离 workspace；
- 明确的权限；
- 有界时间和预算；
- 独立验收命令；
- 可解释的失败分类；
- 不需要模型临时决定生产操作。

## 流水线阶段

~~~text
校验输入
  → 准备 workspace
  → 选择固定 profile
  → 启动 dsh
  → 捕获结果
  → 执行验收
  → 检查 diff/产物
  → 需要时提交人工审批
  → 清理
~~~

不要让 Agent 自己改变 CI 的 profile、Provider、权限或验收脚本。

## 产物

保存最少但足够复现的信息：

- 构建 ID 和任务 ID；
- dsh、Node/Python、Provider 和模型版本；
- profile 名称和非敏感配置摘要；
- session 的内部引用；
- stdout/stderr 脱敏摘要；
- 退出码；
- 测试和验收结果；
- diff 统计；
- 清理状态。

完整 session 日志只放到受控存储，并设置保留时间。

## 失败门禁

以下任一情况不要自动合并：

- dsh 退出码非零；
- 验收命令失败；
- diff 包含允许范围外文件；
- 依赖或锁文件改变但未批准；
- 输出含疑似秘密；
- session 或 workspace 未清理；
- 结果需要人工判断。

## CI 中的网络

明确区分：

- npm/pip 下载；
- Provider 请求；
- 模型目录查询；
- Git 远程；
- 测试使用的服务；
- Agent 工具访问的网络。

CI 允许网络不等于任务可以访问任意 URL。为 Provider、包源和工具分别列白名单或策略。
