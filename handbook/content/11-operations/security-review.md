# 团队安全评审

## 评审范围

评审一个 dsh profile、插件或自动化任务时，覆盖：

- 代码和依赖；
- Provider、endpoint 和凭据；
- 工具和 schema；
- workspace/cwd；
- 文件、Shell、进程和网络；
- 权限、审批、沙箱；
- session、日志和保留；
- 失败、取消和清理；
- 版本和回滚。

## 评审问题

### 输入

- 任务来自哪里；
- 仓库内容是否可能包含 prompt injection；
- 是否限制了路径、长度和字段；
- 是否有真实秘密或个人数据。

### 行动

- Agent 能调用哪些工具；
- 工具能看到哪些进程和环境；
- 是否可以访问 workspace 外；
- 是否可以安装、联网、后台运行或委派；
- 高影响动作由谁批准。

### 输出

- Provider 收到什么；
- session 保存什么；
- 日志会不会进入公共构建产物；
- 结果如何脱敏；
- workspace 如何验收和清理。

### 失败

- 缺凭据怎么办；
- 工具失败怎么办；
- 进程挂起怎么办；
- 测试和最终回答冲突怎么办；
- 取消后如何确认没有遗留；
- 版本升级如何回滚。

## 评审结论

结论使用：

~~~text
通过：已满足范围和验收
有条件通过：需要指定限制或人工审批
不通过：存在未控制的越界/数据/回滚风险
待补充：缺少事实，不能判断
~~~

不要用“看起来安全”作为结论。每个条件都指向一个配置、命令、代码、日志或负责人。
