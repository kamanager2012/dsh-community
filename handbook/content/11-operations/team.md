# 团队运行规范

## 统一但不强行统一

团队应该统一：

- 支持的 dsh 和 Node 版本；
- 推荐 profile；
- Provider ID 和模型命名；
- workspace 创建方式；
- 默认权限；
- 日志脱敏；
- 任务模板；
- 交付和回滚格式。

团队不必统一：

- 每个人的编辑器；
- 个人只读分析 prompt；
- 不影响共享环境的临时 overlay；
- 适用于不同项目的测试命令。

## 任务责任

每个自动化任务都应有：

| 角色 | 责任 |
| --- | --- |
| 请求人 | 目标、范围、数据分类 |
| 批准人 | 权限、网络、不可逆动作 |
| 执行者 | 运行、日志和现场 |
| 验收人 | 测试、diff、业务结果 |
| 维护人 | profile、插件和升级 |

小任务可以一人多角，但不能让“模型最后一句话”同时承担执行和验收。

## 共享配置

共享 profile 进入受控版本库，内容包括：

- 组合和 patch；
- 非敏感默认值；
- Provider ID 和模型 ID；
- 权限与审批策略；
- 兼容版本；
- 使用说明。

凭据、私有 endpoint token、个人路径和 session 不进入共享配置。

## 变更流程

配置变更先在临时 DSH_HOME 验证，再更新团队 profile。提交说明写：

~~~text
变更：
影响的 profile：
增加/删除的工具：
权限变化：
网络变化：
兼容版本：
回滚：
~~~

## 人工介入标准

以下情况转人工：

- 需要生产写入；
- 需要读取受监管数据；
- 失败原因不明确；
- 验收和模型回答冲突；
- 需要提高权限；
- Provider 或插件行为不在兼容矩阵；
- session 状态无法确认。
