# 完整任务示例

下面的示例是任务文本和验收结构，不是已经完成的运行报告。路径、模型和命令需要替换成你的项目实际值。

## 示例一：只读仓库导览

~~~text
目标：说明当前仓库的目录结构、主要模块、构建入口和测试入口。
workspace：当前选中的干净 checkout。
允许：读取 README、配置、源码和测试。
禁止：写文件、安装依赖、联网、访问凭据和 workspace 外路径。
方法：先列顶层目录，再读取入口文件和测试脚本；不要扫描依赖目录。
输出：事实、推断、不确定项三组；每条关键结论附文件路径。
验收：git status --short 为空；回答不声称运行过未运行的命令。
~~~

## 示例二：修复一个失败测试

~~~text
目标：修复 tests/unit/foo.test.ts 中的失败。
范围：src/foo.ts 和对应测试；不改 package.json、锁文件和其他模块。
步骤：先复现失败；定位根因；提出最小修改；运行相关测试。
禁止：不删除断言、不跳过测试、不安装依赖、不提交 commit。
验收：npm test -- foo.test.ts；npm run typecheck；git diff --check。
停止：需要修改范围外文件、联网或提高权限时先询问。
交付：修改文件、根因、命令和退出码、剩余风险、回滚方式。
~~~

## 示例三：文档迁移

~~~text
目标：将旧版安装说明迁移为当前 Web UI 手册。
依据：官方中文 README、Web 指南、Provider 指南和当前仓库文件。
范围：只修改 docs/guide/。
禁止：不把旧截图中的字段当作当前行为；不编造运行结果；不写真实凭据。
要求：每条命令说明入口和版本注意；保留用户可执行的验收。
验收：相对链接、代码块、术语、敏感模式和重复段落检查。
~~~

## 示例四：Headless CI

~~~text
目标：在隔离 checkout 中运行只读仓库检查并输出报告。
输入：经过校验的任务字段，不接受任务字段之外的命令。
权限：只读 workspace；不安装、不联网扩展、不访问凭据。
输出：任务状态、退出码、检查过的文件、测试结果和不确定项。
外层脚本：创建 workspace、执行 dsh、捕获 stderr、运行独立验收和清理。
失败：非零退出、验收失败、超时、遗留进程或清理失败都进入人工处理。
~~~

## 示例五：Provider 对照

~~~text
目标：比较 Provider A 和 Provider B 完成同一只读任务的可用性。
控制变量：相同 workspace 副本、任务文本、权限、超时和验收。
每个 Provider：新 session、记录协议和模型 ID、不记录密钥。
比较：请求成功、工具调用、错误、延迟、成本、结果和数据流。
禁止：把 A 的 session 交给 B，或用最终回答替代外部检查。
~~~

## 示例六：插件能力评审

~~~text
目标：评审插件 X 是否适合团队 profile。
检查：新增服务、工具、事件、权限、网络、凭据、日志和 teardown。
范围：临时 DSH_HOME、最小 workspace。
禁止：生产数据、未批准 endpoint、永久 profile 写入。
交付：能力清单、数据流、兼容版本、失败行为、回滚和安装建议。
~~~
