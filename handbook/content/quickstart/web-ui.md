# Web UI：从启动到交付

本页覆盖第一次使用 dsh 的完整路径：准备工作区、启动 Web UI、配置模型、提交任务和检查结果。官方操作入口见[中文 Web 指南](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/index.zh.md)。

## 先准备工作区

第一次使用建议选择干净的临时 checkout 或可恢复的副本。不要直接把包含密钥、客户资料或未提交重要改动的生产目录交给代理。

开始前确认：

- 你知道工作区的绝对路径；
- 你知道如何运行项目的测试或检查命令；
- 工作区中的现有改动已经记录；
- 不需要把真实密钥写进任务、截图或日志。

可以先在项目目录运行：

```bash
node --version
pwd
git status --short
```

## 1. 启动 Web UI

```bash
npx @deepseek-ai/dsh web
```

默认地址是 `http://127.0.0.1:3080`。需要指定端口时：

```bash
npx @deepseek-ai/dsh web --port 3081
```

启动后只通过本机地址访问，不要把开发服务直接暴露到公网。遇到参数问题，先查看：

```bash
npx @deepseek-ai/dsh --help
npx @deepseek-ai/dsh web --help
```

## 2. 配置模型

打开 **Settings → Models**，选择已安装 Provider 或添加自定义 Provider，保存凭据，然后选择用于新会话的模型。

凭据规则：

- 密钥只通过 Harness 的凭据设置管理；
- 不把密钥写入任务文本、仓库、shell 历史、截图或日志；
- 不提交 `$DSH_HOME/.credentials.yaml`；
- 只在受控位置记录变量名、Provider ID 和模型 ID，不记录密钥值。

Provider 的端点、模型目录、自定义模型和图片输入配置见[模型与 Provider](providers.md)。

## 3. 选择 workspace

在 Web UI 中添加并选中项目目录。选择 workspace 以前，通常不能提交会话任务。

请区分：

| 概念 | 含义 |
| --- | --- |
| cwd | dsh 进程启动时的默认目录 |
| workspace | 当前会话允许代理观察和操作的工作区 |
| session | 本次对话、工具事件和状态的持久边界 |

发送第一条任务前，人工确认 UI 显示的 workspace 是预期目录。路径不确定时停止，不要让模型替你猜。

## 4. 提交一条受控任务

不要只写“帮我看看这个项目”。可以从下面的只读模板开始：

```text
目标：总结项目的目录结构、主要包和可运行的测试入口。
范围：只读取当前已选 workspace；不要访问 workspace 之外的文件。
禁止：不要创建、修改、删除文件；不要安装依赖；不要联网查资料。
完成标准：列出结论所依据的文件，并给出可由我复查的测试或构建入口。
停止条件：如果需要写入、安装、联网或更高权限，先停下来询问。
```

需要修改代码时，明确列出允许修改的目录、禁止操作、验收命令和回滚方式。通用模板见[任务契约](../core/task-contract.md)。

## 5. 检查结果

不要把代理的最后一句话当作验收结果。至少检查：

1. 是否只访问了约定的 workspace；
2. 是否出现了未授权的写入、安装、联网或权限请求；
3. 关键结论是否能回到文件、命令或测试；
4. 工作区是否出现了预期之外的改动；
5. 失败时是否明确说明停在哪一步。

代码任务完成后在终端运行：

```bash
git status --short
git diff --stat
git diff --check
```

再根据项目情况运行测试、构建或类型检查。验收命令必须由你或独立脚本执行，不能只依赖代理自报结果。

## 6. 需要停止的情况

遇到以下情况先暂停会话：

- workspace 不是预期目录；
- 任务需要切换到更高权限；
- 只读任务变成写入、安装或联网；
- Provider、模型或 session 发生了未解释的切换；
- 测试失败但回答仍声称成功；
- 需要恢复旧 session，却无法确认其上下文和持久 Shell 状态。

停止并不等于失败；在边界不清楚时保留现场、询问并重新定义任务，通常比继续猜测更安全。
