# 在 AIOS Core 上做一次只读分析

这是一个可选的任务示例，用来把本手册的 Web UI、任务契约和只读边界放到真实 TypeScript 项目上。它不是 benchmark，也不是对模型“聪明程度”的评分；重点是让输出可以回到文件和命令。

## 适用场景

你希望代理：

- 识别项目的目录结构、架构和测试入口；
- 区分文档、源码和测试之间的表述差异；
- 在只读模式下停止，不修改项目；
- 对每个重要结论列出依据和不确定项。

## 任务前准备

选择一个干净、可丢弃或可恢复的 AIOS Core checkout，确认：

```bash
git status --short
```

不要把包含个人凭据或不可提交数据库的目录直接交给代理。任务文本中明确写出工作区路径和禁止访问的文件。

## 可直接使用的任务文本

```text
目标：只读分析当前 AIOS Core 工作区的目录结构、主要模块、治理约定和测试入口。
范围：只读取当前 workspace；不要访问 workspace 之外的路径。
禁止：不要创建、修改或删除文件；不要安装依赖；不要联网；不要读取 cc-switch.db 或任何凭据文件。
要求：每个关键结论列出文件路径和相关命令；明确区分文件事实、推断和不确定项。
完成标准：返回目录概览、测试入口、主要风险和未解决问题；工作区保持无 diff。
停止：如果需要提高权限、访问被排除的文件或扩大范围，先停下来询问。
```

## 完成后检查

```bash
git status --short
git diff --stat
git diff --check
```

如果出现写入、依赖安装、联网、越权访问或无法解释的模型结论，先停止并重新定义任务。
